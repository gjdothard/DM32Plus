# P25 CPS integration record

Updated: 2026-11-18. CPS branch: `codex/p25-cps-integration`, based on
`CPS` at `6ad0902a`. Paired firmware: `codex/p25-integration`, with the
managed programming changes based on `d662773b`. Neither branch is published
by this work. Hardware and release qualification remain open.

## Provenance

The generic settings, mode records, P25 codecs, field descriptions and system
forms reuse MIT RadioFoundry revision
`c34dc440aaf2d3952458bc0bd85b8c56c76f6b23`:

- `site/static/js/codeplug/kv.js`, `modebytes.js`, `mode_p25.js`,
  `channelmodes.js`, `modes.js`;
- `site/static/js/editor/modefields.js`, `modesview.js`;
- missing editor translations from the same revision.

Original notices remain. Local adaptations expose P25 only, preserve this
fork's channel tabs, privacy keys and talkgroup editor, and enforce the
current Phase 1, eight-system and sixteen-control-channel limits. Unknown
record fields and parameter tails survive supported edits. No foreign radio
firmware implementation was consulted.

that source is unchanged by this work. This is separate from the passing
catalog checks and the CPS regression set. Full CI and installer packaging
remain required before release.

## Operator behavior

See [programming](../user/04-programming.md#p25-programming) and the
[managed transfer contract](../spec/cps-fast.md#managed-mode-aware-programming).
Binary backups preserve P25; lossy channel CSV/qdmr operations are refused.
Adding P25 migrates validated legacy DMR assignments into the shared pool.
Unknown occupied storage and capacity failures stop the operation. Firmware
without managed staged transfers is refused before writing P25 records.
