# P25 foundation

Status: integration in progress. Build switches can select the imported engines,
but default off. A conventional mode-owner component now connects the engines,
voice path and codec loan. Stored conventional channels now use normal channel
selection and PTT. [Trunked dispatch](p25-trunking.md) now uses the same owner
and transmit safeguards. Mode-aware UI/CPS editing remains pending.
The [feature matrix](../feature-matrix.md) remains the source of board support.

## Scope

The foundation implements Phase 1 C4FM framing, channel coding, conventional
voice calls, IMBE voice processing, and trunked control-channel following. It
comes from the project's permissively licensed upstream, pinned in
[the provenance record](../../core/p25/UPSTREAM.md).

| Layer | Responsibility |
|---|---|
| `core/fec` | BCH, Golay, Hamming, Reed-Solomon, convolutional and trellis coding |
| `core/air` | Symbol framing, provider sessions, discriminator-sample soft modem |
| `hal/hal_air.h`, `hal/hal_baseband.h` | Symbol and sample provider contracts |
| `core/dsp`, `core/mbe` | Fixed-point kernels and full-rate voice encoding/decoding |
| `core/p25` | Data units, receive/call engines, voice buffering, signaling and follower |

The [air-interface contract](air-interface.md) describes ownership. The
HR_C7000 provider has been imported and tested on simulated registers against
the existing DMR driver. Platform ownership and interrupt routing are host
tested. Board attachment and PCM gate callbacks are now connected in integration
builds; target timing and resource qualification remain pending.
This is not an on-radio qualification claim.

Protocol engines take time and samples from callers. They contain no board
selection, RTOS calls, blocking waits, or direct RF ownership. The firmware's
existing AMBE frame interface is retained; optional vocoder state loans provide
memory for mutually exclusive modes.

## Workspace ownership

`p25_workspace_t` groups voice, engine and optional trunk follower state. The
engine already contains its air session; the provider's soft modem remains in
its existing queue overlay. No second permanent P25 buffer is allocated.

`p25_workspace_acquire` requests an aligned loan from the optional vocoder
provider and clears the workspace. Unsupported, busy or undersized providers
fail admission. A malformed provider result is returned immediately; if that
cleanup fails, the lease remains available for retry instead of losing it.
Callers must check acquisition success before using the data.

The mode owner stops AMBE before acquisition and stops P25 voice and air
callbacks before `p25_workspace_release`. The loan restores AMBE availability
and forces fresh codec state on its next frame. See the
[codec memory contract](codec-placement.md#idle-codec-state-loans).
These helpers are not yet called by a radio channel owner. They do not start
audio, acquire RF, or grant transmit permission.

## Transmit permission requirement

The intended product supports conventional and trunked Phase 1 receive and
transmit. The existing CPS RX-only channel option must inhibit transmission.
On trunked channels it also inhibits automatic registration, affiliation and
voice requests. A system's listen-only setting independently inhibits transmit.
When both channel and system allow transmit, retain upstream's active path
subject to the radio's normal admission checks.

The imported follower also contains upstream's transmit state machine. Its
`P25_FOLLOW_TX` flag enables that path; an RX-only owner must leave it clear.
`P25_FOLLOW_NO_REG` alone does not disable transmit: it allows requests without
registration. No current firmware owner instantiates the imported follower.

Future integration must enforce RX-only through system and channel records,
validate grant frequencies through board capabilities, and prove no TX requests
on RX-only PTT, acquisition, failure, retuning, or restart. Phase 2,
encryption, LSM/CQPSK and new receive bands are outside the initial scope.

## Conventional mode owner

`radio_p25` adapts upstream's conventional lifecycle and stored parameters.
It currently accepts stored conventional channels only. Trunked channels,
VFO operation and RAM settings overrides are not enabled by this component.

The caller stops DMR/AMBE and tunes the board in digital mode before begin.
The owner rejects active AMBE streaming, an unsupported receive frequency,
missing PCM callbacks, a provider without receive capability, a stale channel
snapshot or an unavailable codec loan. It allocates the engine, voice state
and channel snapshot in one sized loan; no second permanent workspace exists.
It starts the voice path before opening the engine so immediate receive events
have valid storage. A failed open or a settings change during open unwinds it.

The owner prepares and starts modulation only with current stored voice-TX
permission, a TX-capable provider and an allowed transmit frequency. Failed
PCM start discards queued symbols. A refused provider start also discards its
primed queue; clearing TX state cannot reuse an old header. Natural completion
finishes the current unit and terminator. Abort stops modulation and unkeys.

The state-machine caller performs normal inhibition, battery, busy-channel,
timeout, power and RF checks. It holds the recursive storage lock across the
final prepare/check/key/go sequence so a settings writer cannot change permission
between those steps. The owner never keys RF; it unkeys on teardown, abort,
failed go and clearing completed TX. Teardown closes the air provider, unkeys,
stops PCM callbacks and only then returns the loan. A failed return retains
the lease for retry and blocks another begin.

Base-record and full-width keyed-store generations identify the session's
settings. A mismatch refuses prepare/go; the owner's next poll closes the
session. The 8-bit UI/cache serial is not sufficient: 256 keyed edits must
still invalidate an old session. Writer-side quiescence before committing or
acknowledging an RX-only edit remains required for runtime RF guarantees.

The radio state machine selects the owner for a stored conventional P25 tag.
It stops DMR before borrowing codec memory and returns that memory before
entering FM or DMR. A failed return parks the channel. Unsupported tags, stale
bindings and unreadable recognized metadata park with no transmit path, even
when P25 is compiled out. The generic format guard is always built; protocol,
voice and owner code remain behind `CONFIG_P25`.

PTT uses normal RX-only, inhibition, battery, busy-channel, band, power and
timeout checks. Release finishes the terminator; abort and invalidation unkey.
P25 owns PCM exclusively and shares the voice beep mixer and mic-gain policy.
Host-stream PTT is refused until its P25 audio routing is integrated; it must
not silently substitute microphone audio. Any enabled BCL setting refuses an
active P25 receive call. Raw-carrier busy detection needs hardware qualification.
Scanning and dual watch skip tagged channels. The UI refuses a dual-watch pair containing P25 in either pane,
including saved pairs, and reports "Dual watch unavailable for P25". A change to P25 ends an active watch.
Tagged channels cannot start
APRS, hotspot operation or VFO copying. The home screen identifies P25.

Legacy CPS and raw codeplug transfers refuse writes while tagged channels
exist, and cannot overwrite the managed metadata sector. Reads remain allowed.
This prevents permission-blind edits before a mode-aware writer is available.
An internal configuration change invalidates the owner on its next poll;
future mode-aware external writers must quiesce it before acknowledging a
permission change. No synchronous external permission-update API is provided yet.

## Host checks

`make -C tests/host run-p25` builds and runs the foundation tests. They also run
as part of the normal host suite. `p25EngineTest` builds without trunking;
`p25EngineTestTrunk` builds the same engine tests with trunking enabled.
`boardAirTest` checks optional board providers through the real session:
missing and unsupported providers, failed acquisition, RX-only provider TX
refusal, retune, release, and retained TX capability. A provider's capability
does not grant a channel transmit permission. Existing boards leave the new
`board_t.air` and `board_t.baseband` fields NULL until a provider is wired.

`p25TrunkTest` checks control signaling, retunes, noisy sample streams, and a
passive case that presses PTT and verifies zero sends and registration off.

Natural voice completion honors the audio provider's optional `spk_pending`
hook before closing speaker routing. While pending, it supplies silence without
concealment or underrun accounting. Forced stop still closes immediately.
`p25VoiceTest` and `ambeVoiceTest` check buffered-tail completion for both codecs.

`radioP25OwnerTest` connects real stored records, framing, call processing,
IMBE and PCM voice to simulated air/RF/audio/loan providers. It receives a
clear call through symbols into PCM, transmits a call that a reference receiver
decodes, refuses RX-only TX, and checks failed open/audio/go, stale settings,
out-of-band frequencies, RX-only providers and failed loan return. It checks
cleanup order and invalidation after a complete low-byte serial wrap. The
same conventional cases run with trunking compiled on and off.

`radioP25StateTest` uses the real state machine, DMR stack and stored P25
owner with simulated hardware. It checks channel transitions, receive state,
PTT admission, timeout, graceful release and permission revocation during TX.
`radioP25OffTest` checks unsupported-tag parking with P25 compiled out.
`tests/hil/test_p25.py` provides an opt-in-session, read-only owner visibility
check on a preprogrammed channel; it does not qualify RF or audio.
`radioP25TrunkStateTest` adds the stored trunked radio lifecycle, passive receive,
subscriber signaling, granted voice and permission cancellation cases.

`p25BuildTest.py` tests the actual Make source selection, compiles and links
the emitted configurations with P25/trunking on and off, rejects invalid
dependencies, checks the disabled provider, and checks conditional IMBE license
attribution. `hrc7000AirTest` exercises the provider on simulated registers.

These are deterministic software checks, including internally modeled systems.
They do not establish live-system interoperability, voice quality on hardware,
radio-level isolation. Target resource evidence is recorded in the integration
tracker. Later stages add mode-aware editing, then qualify the
board/PCM connection and its build switches on the target.
