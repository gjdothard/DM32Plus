# P25 foundation

Status: integration in progress. Build switches can select the imported engines,
but default off. They do not yet add a working channel mode, provider owner,
UI, or CPS records.
The [feature matrix](../feature-matrix.md) remains the source of board support.

## Scope

The foundation implements Phase 1 C4FM framing, channel coding, conventional
voice calls, IMBE voice processing, and trunked control-channel following. It
comes from the project's permissively licensed upstream, pinned in
[the provenance record](../../core/p25/UPSTREAM.md).

| Layer | Responsibility |
|---|---|
| `core/fec` | BCH, Golay, Hamming, Reed-Solomon, convolutional and trellis coding |
| `core/air` | Symbol framing, provider sessions, discriminator-sample soft modem |
| `hal/hal_air.h`, `hal/hal_baseband.h` | Symbol and sample provider contracts |
| `core/dsp`, `core/mbe` | Fixed-point kernels and full-rate voice encoding/decoding |
| `core/p25` | Data units, receive/call engines, voice buffering, signaling and follower |

The [air-interface contract](air-interface.md) describes ownership. The
HR_C7000 provider has been imported and tested on simulated registers against
the existing DMR driver. Platform ownership and interrupt routing are host
tested; board attachment and audio-gate callbacks remain to be connected.
This is not an on-radio qualification claim.

Protocol engines take time and samples from callers. They contain no board
selection, RTOS calls, blocking waits, or direct RF ownership. The firmware's
existing AMBE vocoder interface remains unchanged.

## Transmit permission requirement

The intended product supports conventional and trunked Phase 1 receive and
transmit. The existing CPS RX-only channel option must inhibit transmission.
On trunked channels it also inhibits automatic registration, affiliation and
voice requests. A system's listen-only setting independently inhibits transmit.
When both channel and system allow transmit, retain upstream's active path
subject to the radio's normal admission checks.

The imported follower also contains upstream's transmit state machine. Its
`P25_FOLLOW_TX` flag enables that path; an RX-only owner must leave it clear.
`P25_FOLLOW_NO_REG` alone does not disable transmit: it allows requests without
registration. No current firmware owner instantiates the imported follower.

Future integration must enforce RX-only through system and channel records,
validate grant frequencies through board capabilities, and prove no TX requests
on RX-only PTT, acquisition, failure, retuning, or restart. Phase 2,
encryption, LSM/CQPSK and new receive bands are outside the initial scope.

## Host checks

`make -C tests/host run-p25` builds and runs the foundation tests. They also run
as part of the normal host suite. `p25EngineTest` builds without trunking;
`p25EngineTestTrunk` builds the same engine tests with trunking enabled.
`boardAirTest` checks optional board providers through the real session:
missing and unsupported providers, failed acquisition, RX-only provider TX
refusal, retune, release, and retained TX capability. A provider's capability
does not grant a channel transmit permission. Existing boards leave the new
`board_t.air` and `board_t.baseband` fields NULL until a provider is wired.

`p25TrunkTest` checks control signaling, retunes, noisy sample streams, and a
passive case that presses PTT and verifies zero sends and registration off.

`p25BuildTest.py` tests the actual Make source selection, compiles and links
the emitted configurations with P25/trunking on and off, rejects invalid
dependencies, checks the disabled provider, and checks conditional IMBE license
attribution. `hrc7000AirTest` exercises the provider on simulated registers.

These are deterministic software checks, including internally modeled systems.
They do not establish live-system interoperability, voice quality on hardware,
target memory fit, or radio-level isolation. A later stage adds board/radio/CPS
integration, feature switches, debug-link visibility and opt-in HIL coverage.
